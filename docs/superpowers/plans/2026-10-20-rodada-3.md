# Rodada 3: plano de implementação

> Registro histórico: plano executado; o código atual pode ter mudado depois.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fechar as pendências da rodada 2 e deixar o site pronto para publicar. Isso inclui metadados de busca e compartilhamento, uma checagem de lançamento, o aviso de privacidade, a página 404 e um código mais organizado. Cada mudança é provada por teste.

**Architecture:**

- `src/data/site.ts` concentra a identidade da página.
- O `Base.astro` monta o `<head>` a partir dela e ganha o modo `interactive={false}` para as páginas secundárias.
- Endpoints do Astro geram `robots.txt`, `sitemap.xml` e `wordmark.svg` a partir dos dados.
- Um script com Playwright gera uma vez as imagens que ficam em `public/`.
- A checagem de lançamento é lógica pura com testes, mais um executável.

**Tech Stack:** Astro 7.4, TypeScript strictest, Vitest 5, Playwright 1.64.1 (Chromium, Firefox, WebKit), Node ≥ 22.22.3 (roda `.ts` direto).

**Spec:** `docs/superpowers/specs/2026-10-20-rodada-3-design.md` (I51–I61, e mais I47 e I49 da rodada 2). Os textos fixos estão na spec: copie de lá, não daqui.

## Global Constraints

- pt-BR em textos, comentários e docs; identificadores em inglês. Comentários no tom e na densidade dos arquivos vizinhos.
- Só devDependencies. Nenhuma requisição a terceiros na página: `tests/e2e/fonts.spec.ts` "nenhuma requisição a terceiros" continua verde, e o teste novo de privacidade também cobre as páginas novas.
- Nenhum dado do Diogo inventado: placeholders `[…]` ficam como estão.
- Toda mudança na tela tem ID I51–I61 (ou I47/I49). Fora deles, nenhum snapshot de `tests/visual` pode mudar. Quando um ID muda a tela, gere os snapshots de novo com `npm run test:visual -- --update-snapshots` e olhe cada imagem alterada.
- Ao fim de cada task, `npm run verify` verde (três motores mais visual). Um teste que falhe uma vez só sob carga é repetido isoladamente com `--repeat-each=10` antes de ser chamado de instável, e o resultado vai para o relatório da task.
- Testes de comportamento não se acoplam a classes de estilo quando há papel, rótulo ou `data-*`.
- Commits pequenos, na branch `refactor/rodada-3`, terminando com a linha `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Nunca adicione `message.txt` nem `saas.pdf` (são do usuário).

## Review Focus

1. **Sem `site` definido**, que é o estado de hoje: o build não quebra, não sai nenhuma URL relativa em `og:image`, canonical ou `Sitemap:`, e a checagem de lançamento aponta isso (Task 5 e Task 7).
2. **Páginas secundárias sem o módulo da página:** `/privacidade` e `/404` aparecem inteiras, sem bloco escondido e sem erro no console, nos três motores (Task 6).
3. **Link do aviso dentro do rótulo do checkbox:** clicar no link abre o aviso em outra aba e **não** marca o checkbox. Clicar no texto continua marcando (Task 6).
4. **Placeholders em atributos e no JSON-LD:** a checagem pega `[UF]` dentro de `content=""`, de `aria-label` e de valores do JSON-LD, mas não reprova arrays do JSON (`["a"]`) nem colchetes dentro de `<script>` comum (Task 7).
5. **Refatorações de componentes:** o HTML gerado de `index.html` é o mesmo antes e depois, salvo atributos de escopo do Astro (Task 3).

**Files:**

**Interfaces:**

- `interface LaunchIssue { file: string; kind: 'placeholder' | 'example-domain' | 'generic-linkedin' | 'missing-canonical'; excerpt: string }`
- `findPlaceholders(text: string): string[]`, com a regra da spec.
- `checkHtml(file: string, html: string, options: { isHome: boolean }): LaunchIssue[]`.
  - Antes de procurar, ela tira o conteúdo de `<script>` comum e de `<style>`.
